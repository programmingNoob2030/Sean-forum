### 4.4.3 Redis 缓存后性能表现

在索引优化后的基础上，为验证 Redis 缓存对 RECENT 排序接口高并发性能的改善效果，本轮测试直接选取索引优化后已确定的性能退化区间进行测试，不再重复进行 coarse 与 fine 阶段的拐点搜索。

测试条件与前序测试保持一致，仅在接口中加入 Redis 缓存。缓存采用 Cache-Aside 策略，缓存有效期设置为 **10 秒**。本轮测试主要观察缓存命中情况下接口的响应性能。

#### 测试数据

| Threads | Requests | Success | Avg (ms) | Min (ms) | Max (ms) | P95 (ms) | P95 涨幅 |
| ------- | -------- | ------- | -------- | -------- | -------- | -------- | -------- |
| 76      | 760      | 100%    | 4        | 1        | 44       | 10       | —        |
| 78      | 780      | 100%    | 3        | 1        | 37       | 5        | -50.00%  |
| 80      | 800      | 100%    | 3        | 1        | 34       | 5        | 0.00%    |

#### 性能表现

在 76～80 threads 的测试区间内，接口 P95 均维持在 **5～10 ms**，未出现前序索引优化测试中明显的响应时间增长。

其中：

- 76 threads：P95 = 10 ms；
- 78 threads：P95 = 5 ms，较 76 threads 下降 50.00%；
- 80 threads：P95 = 5 ms，与 78 threads 持平。

三组测试均保持 **100% 请求成功率**。

与索引优化后的测试结果相比，原本在 76～78 threads 附近出现的明显性能退化，在加入 Redis 缓存后未再次出现。说明在本次测试范围内，缓存命中后请求无需重复执行原有的数据库排序查询，高并发下的响应时间得到明显改善。

#### 结论

本次测试表明，在原有索引优化基础上加入 Redis 缓存后，RECENT 排序接口在 **76～80 threads** 的原性能退化区间内保持了较低且稳定的响应延迟。

因此，在本次测试数据范围内，可以认为 **Redis 缓存有效缓解了高并发场景下 RECENT 排序查询带来的性能压力**，原先约 76～78 threads 开始出现的性能退化现象在缓存命中路径下未再出现。

需要说明的是，本轮测试验证的是**缓存命中场景**，测试结果主要反映 Redis 直接返回缓存数据时的性能表现，并不代表 Redis 在无限并发下不存在性能瓶颈。
