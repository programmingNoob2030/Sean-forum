## 4.4 Indexed / Fine：索引优化后的拐点定位

在 `pure/fine` 阶段已经确定 RECENT 排序在高并发下会出现明显的性能退化，因此在增加排序相关索引后，进一步围绕原始拐点区域进行细粒度测试。

本阶段不再从低并发开始测试，而是重点观察 **70～80 threads** 区间内 P95 延迟的变化，以判断索引优化后性能退化的区间是否发生变化。

### 4.4.1 测试结果

| Threads | Avg (ms) | Min (ms) | Max (ms) | P95 (ms) | P95 涨幅 |
| ------- | -------- | -------- | -------- | -------- | -------- |
| 70      | 31       | 23       | 62       | 49       | —        |
| 72      | 32       | 23       | 100      | 53       | +8.16%   |
| 74      | 31       | 23       | 64       | 51       | -3.77%   |
| 76      | 45       | 24       | 149      | 63       | +23.53%  |
| 78      | 85       | 24       | 223      | 136      | +115.87% |
| 80      | 90       | 25       | 362      | 167      | +22.79%  |

### 4.4.2 性能退化区间

70～74 threads 范围内，P95 基本维持在 50 ms 左右，整体波动较小。

76 threads 后，P95 开始出现较明显的增长：

- 76 threads：P95 = 63 ms；
- 78 threads：P95 = 136 ms，较 76 threads 上升 115.87%；
- 80 threads：P95 = 167 ms，较 78 threads 继续上升 22.79%。

其中 **76 → 78 threads** 出现了本轮测试中最明显的性能跃升，说明性能退化主要集中在这一并发区间。

因此，本次测试认为，**索引优化后 RECENT 排序的性能退化区间约为 76～78 threads，实际拐点可近似定位在 78 threads 附近。**

### 4.4.3 阶段性结论

与 `pure/fine` 阶段相比，索引优化后，RECENT 排序在相同高并发区间内的 P95 整体有所下降，同时明显退化出现的位置有所后移。

因此，本阶段结果表明：

1. 索引优化后，RECENT 排序在高并发场景下的响应延迟有所降低；
2. 性能退化并未消失，仍然存在明显的并发拐点；
3. 原本约 **50～60 threads** 开始出现明显退化，优化后拐点进一步向 **76～78 threads** 区间移动；
4. 本次测试将优化后的性能拐点近似定位为 **78 threads 附近**。

需要注意的是，JMeter 并发测试存在一定运行时波动，因此这里的“拐点”应理解为一个**性能明显开始恶化的区间**，而不是绝对精确的线程数临界值。
