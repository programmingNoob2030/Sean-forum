# COMMENTS 排序性能

## 测试一 Fine

### 1. 测试目的

评估评论排序接口在不同并发线程数下的响应性能，观察随着并发压力增加，接口 P95 延迟的变化趋势，并确定性能开始明显退化的并发区间，为后续优化提供基准数据。

### 2. 测试条件

- 测试工具：Apache JMeter 5.6.3
- 测试接口：Comments 排序
- 排序参数：`COMMENTS`
- Ramp-Up：10s
- 每个线程循环次数：10
- 并发线程数：10 ～ 100
- 每组请求数：`threads × 10`
- 错误率：0%

### 3. 测试结果

| Threads | P95    | 相对上一级涨幅 |
| ------- | ------ | -------------- |
| 10      | 35 ms  | —              |
| 20      | 35 ms  | 0.00%          |
| 30      | 35 ms  | 0.00%          |
| 40      | 37 ms  | +5.71%         |
| 50      | 41 ms  | +10.81%        |
| 60      | 75 ms  | +82.93%        |
| 70      | 129 ms | +72.00%        |
| 80      | 562 ms | +335.66%       |
| 90      | 772 ms | +37.37%        |
| 100     | 918 ms | +18.91%        |

所有测试均无请求错误。

### 4. 结果分析

10 ～ 50 threads 区间内，P95 基本维持在较低水平，仅从 35 ms 上升至 41 ms，整体变化较小。

当并发提升至 60 threads 后，P95 从 41 ms 上升至 75 ms，出现明显性能退化。

继续提高并发后，P95 延迟进一步快速增长，70 threads 达到 129 ms，80 threads 达到 562 ms，说明系统已经进入明显的性能压力区间。

其中 80 threads 时 P95 相较 70 threads 增长 335.66%，表现出非常明显的延迟恶化。

### 5. 拐点判断

当前 Fine 版本的首个明显性能拐点位于 **50 ～ 60 threads**。

50 threads 时 P95 为 41 ms，而 60 threads 时上升至 75 ms，延迟出现明显增长，因此可将 **约 60 threads** 视为当前实现开始明显退化的并发区间。

后续在 80 threads 附近出现第二次显著恶化，但当前实验重点为确定主要性能瓶颈及验证优化效果，因此无需继续向更高并发扩展测试范围。

### 6. 后续优化对照

后续针对 Comments 排序逻辑进行优化后，采用相同测试条件重新进行压测，并重点对比：

- 相同并发下的 P95 延迟
- 首个明显性能拐点的位置
- 高并发区间的延迟增长趋势

重点观察优化后性能退化点是否能够从约 **60 threads** 推迟至更高并发区间。
