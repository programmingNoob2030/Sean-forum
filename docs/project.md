# 项目概览

## 1. 项目简介

Sean's Forum 是一个基于 Spring Boot + Vue 的前后端分离社区论坛系统，围绕用户注册登录、社区板块、帖子发布、评论互动、点赞/点踩、站内消息和最近浏览记录等核心社区场景展开。

项目当前重点解决的是：

- 社区内容的发布与浏览
- 用户之间的评论、评分和通知互动
- 板块、帖子、消息和浏览记录的基础闭环

## 项目定位

类型：
个人学习/求职展示项目

目标：
模拟真实社区论坛业务，练习后端工程能力。

非目标：
不追求大规模生产部署，不引入复杂分布式架构。

## 2. 技术栈

### 后端

- 语言：Java 17
- 框架：Spring Boot 3.5.11
- Web：Spring MVC
- ORM：MyBatis-Plus 3.5.9
- 分页：PageHelper 2.1.0
- 校验：Jakarta Validation / spring-boot-starter-validation
- 认证：JWT（java-jwt）
- 密码加密：jBCrypt
- 缓存与会话：Redis、Spring Session Redis (添加了依赖但未使用)
- 邮件：Spring Boot Mail
- 线程池：Spring Task / ThreadPoolTaskExecutor
- 文件上传：本地文件系统上传，Spring MVC 静态资源映射 `/uploads/**`

### 前端

- 框架：Vue 3
- 构建工具：Vite 8
- 语言：TypeScript
- 状态管理：Pinia
- 路由：Vue Router
- 请求：Axios
- UI：Element Plus

### 数据与运行环境

- 数据库：MySQL 8.x
- 缓存：Redis 6.x 及以上
- 配置：`application.yaml.example` / 前端环境变量

### 运行要求（来自 README）

- JDK 17+
- Maven 3.8+
- Node.js 18+
- MySQL 8.0+
- Redis 6.0+

## 版本来源

- 后端版本：以 `pom.xml` 为准
- 前端版本：以 `package.json` 为准
- 数据库结构：以 `migration/sql` 文件为准

## 3. 当前已实现功能

### 用户模块

- 用户注册
- 用户登录
- JWT 身份认证
- 邮箱验证码校验
- 重置密码
- 个人资料查看与更新
- 头像上传

### 社区 / 板块模块

- 创建社区板块
- 获取社区广场列表
- 获取我的社区
- 搜索社区 (仅用于帖子创建时选择社区)
- 查看社区详情
- 编辑社区信息
- 上传 / 更换社区封面
- 加入 / 退出社区关系切换
- 社区最近浏览记录

### 帖子模块

- 发布帖子
- 帖子分页查询
- 查看帖子详情
- 逻辑删除帖子 (存在数据同步bug)
- 恢复帖子 (还同步UI)
- 帖子最近浏览记录

说明：

- 当前帖子编辑器仍是纯文本输入框，没有发现完整富文本编辑器实现。
- 仓库中已存在帖子标题和正文长度校验，以及 `posts.content` 承载长文本的数据库修改。

### 评论模块

- 发布评论
- 分页获取帖子评论
- 逻辑删除评论 (只有后端接口)
- 恢复评论 (只有后端接口)
- 多层评论结构（根评论 / 子评论）

### 评分模块

- 帖子点赞 / 点踩切换
- 评论点赞 / 点踩切换

### 消息模块

- 获取未读消息数
- 获取消息列表
- 评论、点赞、点踩后发送站内消息 (点赞和点踩都放进点赞里面了)

### 浏览记录模块

- 帖子最近浏览记录
- 社区最近浏览记录
- Redis 保存近期访问 ID，MySQL 保存流水记录

### 已实现的基础设施能力

- 统一返回体 `Result` / `PageResult`
- 全局异常处理
- 登录拦截器
- 可选认证接口标记 `@OptionalAuth`
- 异步线程池
- 事件驱动的计数更新和消息发送

- 但前端帖子编辑区域仍然是普通 textarea，尚未形成完整的图文编辑体验。

## 5. 项目约束

- 当前项目是单体应用，不是微服务系统。
- 现有业务已经通过 Spring MVC + Service + Mapper 分层组织，后续改动应优先延续这一结构。
- Redis 目前承担的是会话、验证码、浏览记录和未读数缓存，不应随意改成复杂中间件方案。
- 文件上传目前依赖本地文件系统和静态资源映射，不建议在没有明确需求时直接切换对象存储。
- 不建议为了“技术关键词”强行引入 MQ、ES、分布式事务、Kubernetes 或复杂 Agent 框架。
- 数据库结构已有一定业务沉淀，变更表结构前要同步检查 Mapper、VO、测试和前端展示逻辑。

## AI Coding 注意事项

- 修改代码前先阅读 architecture.md
- 新功能优先复用已有设计
- 不随意引入新的技术栈
- 修改数据库结构时同步检查：
  Entity
  Mapper
  Service
  Controller
  前端接口
- 修改已有业务逻辑时注意兼容已有接口
