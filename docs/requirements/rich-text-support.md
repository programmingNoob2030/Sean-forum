# Rich Text Support

## 1. 需求概述

当前帖子和评论仅支持纯文本输入，用户无法在帖子正文中表达图片内容，也无法方便地使用 emoji 表情。本需求为发布内容增加基础的图文和表情表达能力，重点改善帖子发布与评论互动体验。

本需求中的“基础富文本”仅包含以下内容：

- 普通文字
- 换行和段落结构
- emoji 表情
- 帖子正文中的内嵌图片

不包含复杂的文字排版和内容编辑能力。

## 2. 功能目标

1. 用户发布帖子时，可以组合输入文字、emoji 和图片。
2. 用户插入的图片应成为帖子正文的一部分，并按照正文内容顺序展示，而不是作为独立附件展示。
3. 用户发布评论时，可以在原有文本评论基础上使用 emoji。
4. 帖子详情、帖子列表相关展示位置和评论区域能够正确呈现已发布的文字、emoji、换行和帖子正文图片。
5. 不破坏现有帖子、评论的发布、浏览、删除、恢复、点赞和通知等业务行为。
6. 富文本内容应只呈现允许的内容，不因用户输入造成页面结构破坏或执行非预期内容。

## 3. 使用场景

### 3.1 发布包含文字和图片的帖子

用户进入帖子发布页面，输入标题，在正文中输入文字，并在指定位置插入一张或多张图片，随后发布帖子。其他用户查看帖子详情时，应按发布时的顺序看到文字和图片，图片属于正文内容的一部分。

### 3.2 发布包含 emoji 的帖子

用户在帖子正文中输入文字并插入一个或多个 emoji，也可以发布仅包含 emoji 的正文（是否允许需要结合最终内容校验规则确认）。发布后，emoji 应以正常可读的表情内容显示。

### 3.3 发布包含 emoji 的评论

用户在帖子下方发表评论时，可以输入普通文字、一个或多个 emoji，或仅输入 emoji。评论发布后，评论内容应正常显示，并继续参与现有的评论计数、评论通知和点赞/点踩流程。

### 3.4 浏览历史内容

用户浏览既有纯文本帖子或评论时，内容显示和原有体验保持不变。富文本能力只影响新增内容的表达和展示，不要求对历史纯文本内容进行迁移或重新编辑。

### 3.5 内容提交失败

当帖子正文中的图片无法完成处理，或内容不符合发布规则时，用户应收到明确的失败提示，且不能产生一条内容不完整的帖子。评论提交失败时，不能产生空评论或半条评论。

## 4. 功能范围

### 4.1 本期范围

#### 帖子发布

- 支持文字输入。
- 支持换行和段落顺序保留。
- 支持在正文中的指定位置插入图片。
- 支持在正文中插入 emoji。
- 支持文字、图片和 emoji 任意组合。
- 发布后在帖子相关展示场景中还原正文的内容顺序和基本结构。
- 图片属于帖子正文内容，不作为独立附件列表、下载项或额外帖子资源展示。

#### 评论发布

- 保留现有文字评论能力。
- 增加 emoji 输入能力。
- 支持文字与 emoji 混合评论。
- 支持仅包含 emoji 的评论。
- 评论不支持插入图片。

#### 内容展示

- 正确展示文字、emoji、换行和帖子正文图片。
- 图片不应遮挡、挤压或破坏正文及评论区域的正常布局。
- 纯文本历史内容继续正常展示。
- 已删除内容和恢复后的内容继续遵循现有业务状态，不因内容形式变化而改变删除、恢复语义。

### 4.2 不在本期范围

- 帖子编辑。
- 评论编辑。
- 评论中插入图片。
- 文件附件、独立附件列表或附件下载。
- 图片之外的媒体内容，例如视频、音频、动图或文件。
- 复杂富文本排版，例如字体、字号、颜色、加粗、斜体、下划线、对齐、列表、表格、引用、代码块或超链接。
- 帖子草稿、自动保存、撤销重做和版本历史。
- 图片裁剪、旋转、压缩、滤镜和批量管理。
- 面向已有历史帖子的内容格式迁移。

## 5. 业务规则

### 5.1 内容组成

1. 帖子正文由文字、emoji 和内嵌图片组成，三者可以按任意顺序组合。
2. 换行和段落顺序属于正文表达的一部分，发布后应保留基本阅读结构。
3. 图片必须出现在正文内容流中，不能脱离正文单独展示为附件。
4. 评论正文由文字和 emoji 组成，不允许插入图片。
5. emoji 应被视为正常内容，而不是被当作无效字符、附件或特殊指令。

### 5.2 内容有效性

1. 帖子仍需满足现有标题和正文长度校验规则。
2. 帖子正文不能提交为空。正文是否允许“仅图片”或“仅 emoji”，需要产品进一步确认；在确认前，验收应至少覆盖“文字 + 图片”“文字 + emoji”和“文字、图片、emoji 混合”三种组合。
3. 评论不能提交为空白内容。
4. 评论允许仅包含 emoji，不能因为没有普通文字而被判定为空评论。
5. 只包含无效内容、已失败的图片或不可展示内容时，不应创建成功的帖子或评论。

### 5.3 图片内容规则

1. 图片只能通过帖子正文插入。
2. 图片插入位置应由用户操作决定，发布后保持与文字、emoji 的相对顺序。
3. 图片处理失败时，帖子不能以缺图或残缺正文状态发布。
4. 图片展示失败时，页面应保持正文其他内容可读，不能导致整个帖子详情或列表无法使用。
5. 图片格式、单张大小、单篇帖子图片数量、总大小、尺寸限制和失败提示文案目前未明确，需要补充确认。

### 5.4 权限与现有业务兼容

1. 帖子发布继续遵循现有登录、社区选择和发布权限规则。
2. 评论发布继续遵循现有登录和评论权限规则。
3. 富文本内容发布成功后，继续参与现有帖子计数、评论计数、消息通知、点赞/点踩、删除和恢复流程。
4. 内容展示不得暴露不应展示的用户或系统信息。

### 5.5 内容安全与可控性

1. 用户内容中仅允许本需求定义的内容类型被展示。
2. 用户输入不应被解释为可执行页面内容，也不应改变页面外层结构。
3. 图片来源必须是系统认可的内容资源；不认可或失效的图片不得以不可控方式加载。
4. 对不支持的内容类型，应拒绝提交或以明确提示告知用户，不能静默生成不可预期的展示结果。

## 6. 交互与体验要求

1. 帖子发布区域应让用户能够明确区分文字输入、emoji 输入和图片插入操作。
2. emoji 选择后应插入到当前编辑位置，不应覆盖已有文字。
3. 图片插入后，用户能够继续在图片前后输入文字或 emoji。
4. 发布前，用户能够看到接近最终展示效果的正文内容。
5. 内容过长、图片不符合规则、图片处理失败或提交失败时，应保留用户仍可继续修改的内容，具体保留方式需结合交互方案确认。
6. 移动端和桌面端均应保证编辑区、正文图片和评论内容可正常阅读，不因内容长度或图片比例导致主要操作不可用。

## 7. 验收标准

### 7.1 帖子发布

- [ ] 用户可以发布包含普通文字的帖子，现有纯文本发布行为不受影响。
- [ ] 用户可以在帖子正文中插入 emoji，发布后 emoji 显示正确。
- [ ] 用户可以在帖子正文中插入图片，发布后图片显示在正文内容流中。
- [ ] 用户可以发布文字与图片混合的帖子，展示顺序与编辑时一致。
- [ ] 用户可以发布文字与 emoji 混合的帖子，展示顺序与编辑时一致。
- [ ] 用户可以发布同时包含文字、图片和 emoji 的帖子，三类内容均可正常展示。
- [ ] 帖子正文中的换行和基本段落结构在发布后可读且顺序正确。
- [ ] 帖子正文图片不会以独立附件列表或额外下载项出现。
- [ ] 图片处理失败时不会创建缺少图片内容的成功帖子，并会显示明确提示。
- [ ] 不符合现有标题或正文长度规则时，帖子不能发布成功。

### 7.2 评论发布

- [ ] 用户可以发布包含普通文字的评论，原有评论能力不受影响。
- [ ] 用户可以发布仅包含 emoji 的评论。
- [ ] 用户可以发布文字与 emoji 混合的评论。
- [ ] 评论中的 emoji 发布后显示正确，评论顺序、评论计数和现有通知行为不受影响。
- [ ] 评论不能插入图片；相关操作不可用或应被明确拒绝。
- [ ] 空白评论不能发布成功。

### 7.3 内容展示与兼容性

- [ ] 帖子详情能够正确展示新增的文字、emoji、换行和正文图片。
- [ ] 帖子列表或摘要展示不会因富文本内容导致页面结构错乱；无法完整展示时应保持合理摘要或截断效果。
- [ ] 评论区域能够正确展示文字和 emoji。
- [ ] 历史纯文本帖子和评论继续正常展示。
- [ ] 删除、恢复、点赞、点踩、评论计数、消息通知等现有流程不因内容形式变化而失效。
- [ ] 不支持的内容不会被执行或造成页面结构破坏。
- [ ] 图片失效时，正文其他文字和 emoji 仍可正常阅读。

## 8. 待补充信息与确认项

以下信息目前未在需求中明确，建议在进入设计和开发前确认：

1. 帖子正文是否允许仅包含图片，或仅包含 emoji。 (帖子正文允许包含文字、emoji、图片的任意组合。允许仅包含图片或仅包含 emoji 的帖子发布。)

2. 图片允许的格式、单张大小、单篇帖子数量、总大小和尺寸范围。(格式为jpg/jpeg/png，单张大小不得超过10mb，一篇帖子支持插入多张图片，不限制业务上的图片数量；但实际上传数量和资源占用受服务器存储能力及上传限制约束。总大小也不限制，尺寸不超过10mb能承受的范围)

3. 图片处理失败时的提示文案，以及是否允许用户移除失败图片后继续发布。(上传失败：该图片不进入正文内容，用户可以继续发布。

   展示失败：显示图片加载失败占位，不影响正文其他内容展示)

4. 是否允许粘贴图片，还是仅允许通过选择文件的方式插入。(选择文件)

5. 是否需要支持拖拽插入图片。(支持拖拽本地图片文件到编辑区域插入)

6. 帖子列表摘要中遇到图片时的展示规则，例如显示图片占位提示、缩略图，或只展示文字部分。(展示帖子的第一张图片的略缩图即可)

7. emoji 的具体范围：仅支持系统/浏览器可输入的 emoji，还是提供固定的表情面板。(浏览器可输入的)

8. 是否需要限制单条帖子或评论中 emoji 的数量。(emoji 数量不单独限制，整体按照评论长度规则校验)

9. 正文长度校验应按用户可见字符、文本字符，还是包含图片占位内容的整体内容计算。(图片不算文本长度, 但emoji正常计算在其中)

10. 图片上传或内容提交期间，用户是否可以离开页面；若可以，是否需要草稿能力。草稿本期默认不包含在范围内。(本次不考虑草稿功能)

在上述信息确认前，本需求文档可作为范围和验收基线；涉及具体限制的验收项应以最终确认值为准。

## 9. 需求边界总结

本功能的核心交付是：帖子支持“文字 + emoji + 正文内嵌图片”的基础内容表达，评论支持“文字 + emoji”的内容表达，并确保发布后的内容可按原顺序展示且兼容现有社区业务流程。

本需求不要求引入复杂富文本能力，也不要求实现附件系统、编辑能力或其他媒体内容。
