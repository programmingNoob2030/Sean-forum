# 帖子搜索功能 V1 需求文档

## 1. 功能背景

当前 Sean's Forum 已支持帖子浏览、分页和多种排序，但用户只能通过浏览列表或社区范围寻找帖子，无法根据帖子内容快速定位目标。需要增加一个简单、可用的帖子搜索能力，降低查找标题或正文相关帖子的成本。

本版本以小范围、低复杂度为目标，直接复用现有帖子列表能力，不建立独立搜索系统。

## 2. 功能目标

1. 用户可以通过关键词搜索帖子标题和正文。
2. 标题或正文包含关键词的帖子均可被检索到。
3. 搜索支持结果分页，并能在分页过程中保持当前关键词。
4. 搜索结果继续支持现有的帖子排序方式。
5. 搜索入口使用现有导航栏搜索框，用户按 Enter 后进入独立搜索结果页面。
6. 无关键词时，现有 `/posts` 行为和普通帖子列表行为保持不变。

## 3. 功能范围

### 3.1 搜索内容

- 搜索帖子标题 `title`。
- 搜索帖子正文 `content`。
- 标题或正文任一包含关键词即可匹配。
- V1 使用简单的模糊包含搜索。
- 搜索暂不区分大小写，具体匹配效果遵循当前 MySQL 字符集和排序规则。

### 3.2 搜索入口

- 使用现有 `components/index/NavBar.vue` 中的搜索框。
- 保留现有搜索框的 UI 样式和基本交互。
- 用户输入关键词后按 Enter 触发搜索。
- 搜索触发后进入搜索结果页面，不打开新的浏览器窗口。

### 3.3 搜索结果页面

- 使用 Vue Router 的独立页面展示搜索结果。
- 页面地址采用 `/search?keyword=xxx` 形式。
- 页面从 URL 查询参数读取当前关键词。
- 页面展示匹配的帖子列表和总数量。
- 搜索结果使用现有帖子展示数据和 `PostVO` 能力。

### 3.4 分页与排序

- 搜索结果必须支持 Element Plus `el-pagination`。
- 翻页时重新请求 `/posts`。
- 翻页请求必须继续携带当前 `keyword`。
- 修改关键词后重新从第 1 页开始。
- 搜索结果继续支持 `RECENT`、`POPULAR`、`COMMENTS`、`HOT` 四种现有排序方式。
- `keyword` 是筛选条件，`sort` 是排序方式，两者独立生效。

## 4. 用户行为

### 4.1 发起搜索

1. 用户在导航栏搜索框输入关键词。
2. 用户按下 Enter。
3. 系统将关键词编码到 `/search?keyword=xxx` 路由中。
4. 搜索结果页面加载并请求帖子列表。
5. 系统展示匹配的帖子、总数量和分页控件。

### 4.2 翻页

1. 用户在搜索结果页面选择其他页码。
2. 系统保持当前关键词不变。
3. 系统请求对应页的 `/posts` 数据。
4. 页面更新帖子列表、当前页和总数量。

### 4.3 修改关键词

1. 用户修改搜索框中的关键词并再次按 Enter。
2. 系统更新搜索结果路由中的 `keyword`。
3. 搜索结果页从第 1 页重新加载。
4. 页面不应沿用旧关键词的结果或旧页码。

### 4.4 空关键词

当关键词不存在、为空或仅包含空格时，系统应视为无有效搜索条件。此时不执行帖子内容过滤，保持现有 `/posts` 的查询行为；搜索页面是否跳转回首页或展示普通帖子列表，应在设计中选择一种一致行为。

## 5. 接口需求

### 5.1 接口

复用现有接口：

```text
GET /posts
```

### 5.2 新增请求参数

```text
keyword
```

示例：

```text
GET /posts?keyword=redis&pageNum=1&pageSize=10&sort=RECENT
```

语义：

> 查询标题或正文包含 `redis` 的帖子，并按 `RECENT` 排序。

### 5.3 参数行为

- `keyword` 不存在或为空时，不增加搜索过滤条件。
- `keyword` 有效时，标题或正文包含关键词即可匹配。
- `pageNum`、`pageSize` 继续遵循现有分页规则。
- `sort` 继续遵循现有排序规则。
- 返回格式保持现有 `PageResult<PostVO>`，不新增搜索专用返回结构。

## 6. 搜索匹配规则

1. 匹配条件为：

   ```text
   title 包含 keyword
   OR
   content 包含 keyword
   ```

2. 标题命中或正文命中均视为匹配成功。
3. 标题和正文同时命中时只返回一条帖子。
4. 搜索不区分大小写。
5. 不对结果进行搜索权重排序。
6. 不要求显示命中位置或高亮关键词。

## 7. 业务约束

1. 搜索只针对帖子，不搜索评论、用户、板块或其他数据。
2. 搜索必须复用现有 `/posts` 接口，不新增独立搜索接口。
3. 搜索必须保留现有帖子排序能力。
4. 搜索必须保留现有分页能力。
5. 搜索不改变帖子详情、点赞、点踩、评论、删除和恢复等已有业务。
6. 搜索不要求引入新的中间件或独立搜索服务。
7. 搜索结果中的帖子展示继续使用现有帖子数据结构和页面能力。

## 8. 非目标

V1 暂不包含以下能力：

- Elasticsearch。
- 分词搜索。
- 搜索权重或相关性排序。
- 搜索建议或联想词。
- 搜索历史。
- 搜索结果高亮。
- 拼音搜索。
- Redis 搜索缓存。
- 独立搜索服务。
- 评论搜索。
- 用户搜索。
- 板块搜索。
- 搜索结果内容摘要的专门生成规则。

## 9. 边界情况

1. `keyword` 缺失时，接口行为与原有 `/posts` 行为一致。
2. `keyword` 为空字符串时，不增加过滤条件。
3. `keyword` 只有空格时，应按无有效关键词处理。
4. 没有匹配帖子时，页面显示空结果状态和总数量 `0` 或沿用项目现有空结果语义，不应出现无意义的全量帖子结果。
5. 关键词包含大小写差异时，匹配行为不应因大小写导致用户无法找到内容。
6. 关键词包含 SQL 通配符或其他特殊字符时，应按普通用户输入处理，不应破坏查询语句或改变查询结构。
7. 关键词过长时，应有合理限制或明确失败提示，不能导致请求无限增长或页面异常；具体上限需在设计阶段确定。
8. 搜索结果只有一页时仍应显示正确的总数量，并按现有页面习惯处理分页控件。

## 10. 验收标准

- [ ] 用户在 `NavBar.vue` 搜索框输入关键词并按 Enter 后，进入 `/search?keyword=xxx` 页面。
- [ ] 搜索不打开新的浏览器窗口。
- [ ] 搜索结果页面能够展示匹配帖子和总数量。
- [ ] 帖子标题包含关键词时能够匹配。
- [ ] 帖子正文包含关键词时能够匹配。
- [ ] 标题或正文任一命中即可返回帖子。
- [ ] 标题和正文同时命中时不会重复返回同一帖子。
- [ ] 搜索匹配不区分大小写。
- [ ] 搜索结果支持 Element Plus 分页。
- [ ] 翻页时保留当前关键词并重新请求 `/posts`。
- [ ] 修改关键词并按 Enter 后从第 1 页重新查询。
- [ ] `keyword` 与 `RECENT`、`POPULAR`、`COMMENTS`、`HOT` 可组合使用。
- [ ] `keyword` 缺失、为空或仅为空格时，现有 `/posts` 行为保持不变。
- [ ] 搜索不匹配评论、用户、板块或其他数据。
- [ ] 不引入独立搜索接口、Elasticsearch、分词、搜索高亮或 Redis 搜索缓存。
- [ ] 搜索结果继续使用现有 `PageResult<PostVO>` 数据结构。

## 11. 待确认事项

以下事项不影响 V1 主流程，但需要在开发前确定默认口径：

1. 空关键词按无条件帖子列表处理时，搜索页面是保留在 `/search`，还是跳转回首页 `/`。
2. 关键词最大长度。设计文档暂按服务端限制为 `100` 个字符处理，开发前如无特别要求可采用该默认值。
3. 没有搜索结果时，页面是复用现有 `el-empty` 文案，还是使用搜索专用提示。
