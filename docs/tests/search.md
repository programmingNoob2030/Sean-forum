# 帖子搜索功能 V1 测试说明

## 测试准备

- 启动后端、前端、MySQL 和 Redis。
- 准备已登录用户和未登录浏览器会话。
- 准备标题、纯文本正文、结构化正文、含中文和 emoji 的帖子数据。
- 准备足够数量的匹配帖子以覆盖分页。

## 功能场景

1. 在导航栏输入关键词并按 Enter，确认进入 `/search?keyword=xxx`，不打开新窗口。
2. 直接访问 `/search?keyword=redis` 或刷新页面，确认关键词恢复并请求 `GET /posts`。
3. 关键词命中标题时，确认帖子返回。
4. 关键词命中正文时，确认帖子返回。
5. 标题或正文任一命中时，确认帖子返回；标题和正文同时命中时只出现一条。
6. 使用大小写不同的关键词，确认匹配行为符合数据库排序规则且不会因大小写无法检索。
7. 使用中文关键词和包含空格的关键词，确认关键词经过路由和请求后仍保持完整。
8. 使用 `%`、`_` 和反斜杠作为关键词，确认按普通字符搜索，不会匹配全部帖子或改变 SQL 结构。
9. 使用 `null`、空字符串和纯空格关键词，确认无内容过滤；搜索页仍能展示普通帖子列表。
10. 使用超过 100 个字符的关键词，确认后端返回明确参数错误，前端不会出现异常页面。
11. 分别使用 `RECENT`、`POPULAR`、`COMMENTS`、`HOT` 与关键词组合，确认结果均仅来自匹配集合且排序语义保持。
12. 翻页后确认请求仍包含当前关键词、sort、pageNum 和 pageSize，total 与匹配总数一致。
13. 在非第一页修改关键词并按 Enter，确认页码回到第 1 页且不显示旧关键词结果。
14. 使用无匹配关键词，确认页面显示空结果状态且 total 为 0。
15. 未登录访问搜索页和 `/posts?keyword=...`，确认可以按项目现有可选认证规则正常查询。
16. 使用 SQL 关键字作为关键词，确认能够正常搜索，不会因为关键词内容改变查询逻辑。

## 缓存边界

1. 观察不带关键词、第一页、无 `boardId` 的首页请求，确认沿用现有 Redis 帖子列表缓存。
2. 观察带关键词、指定 `boardId` 或非第一页请求，确认不会读取或写入现有首页列表缓存。
3. 连续使用不同关键词搜索，确认结果不会相互串用。

### Bug 与修复

1. **搜索空页丢失分页元数据**：`keyword=Vue&pageNum=2&pageSize=3` 原响应为 `total=0,pageNum=1,pageSize=0`，没有保留真实匹配总数及请求页信息。原因是 Service 将 PageHelper 返回的空 `Page` 替换为普通空列表。已修改 `PostServiceImpl`，保留原分页对象交给 `PageInfo`；新增回归测试断言 `total=1,pageNum=2,pageSize=3`，测试通过。
2. **刷新后导航栏未恢复关键词**：直接打开 `/search?keyword=Vue` 时结果页能读取关键词，但导航栏输入框为空。已修改 `ForumIndex.vue`，监听 `route.query.keyword` 并同步至搜索框；浏览器刷新复测后输入框显示 `Vue`。

### 文档与实现差异

- 架构文档写明后端代理目标为 `8088`，当前 `vite.config.ts` 和实际后端均使用 `8080`。
- 超长关键词错误采用 HTTP 200 加统一响应体业务码 `400`，不是 HTTP 4xx。
- 结构化正文以 JSON 字符串存储，SQL 对 `posts.content` 原始存储值执行 LIKE，因此理论上也可能命中 JSON 字段名或图片路径，而不仅是页面可见正文文本。
